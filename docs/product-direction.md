# Product Direction

## 已批准方向

AgentArena 的默认人工入口是 Workbench。启动 `agentarena ui` 后：

- `/` 进入 Workbench。
- `/workbench/` 是主界面。
- `/legacy/` 保留旧版完整视图，用于兼容历史结果、旧深链接和暂未迁移的细节能力。
- 带 `run` 或 `agent` 参数的旧链接会自动进入兼容入口，不改写历史结果。

这不是删除旧版，而是明确一个默认入口，避免新用户在两个主界面之间做无意义选择。

## 当前成功定义

一次有效的首次体验必须满足：

1. 用户能找到合适的任务和 Agent。
2. 运行真正开始，而不是只载入样例数据。
3. 至少一个合格结果完成全部检查。
4. 用户能看到结论、失败原因、改动和回放证据。
5. 已知成本、估算成本和不可用成本不会混在一起。
6. 全部失败时不产生冠军、奖牌或推荐。

## 旧版退出门槛

只有同时满足以下条件，才讨论删除旧版：

- Workbench 覆盖启动、历史、对比、证据、回放、导入、导出和设置等主要流程。
- 旧深链接有迁移方案，历史 `summary.json` 仍可读取。
- 桌面、移动端和键盘流程均通过回归检查。
- 至少完成两次稳定发布，期间没有只能靠旧版处理的高影响问题。
- 在至少 20 个自愿开启本地统计的有效会话中，Workbench 的“打开 → 启动 → 完成 → 查看结果”漏斗达到预设门槛；门槛在收集数据前确定，不用事后挑数字。

## Adapter 冻结

近期不新增 Adapter。原因不是“功能已经足够多”，而是现有路径仍受安装、登录、上游命令格式和系统差异影响。继续扩张会增加表面覆盖，降低真实可用性。

重新开放新增 Adapter 的条件：

- 现有 supported 路径都有可重复的 doctor、登录检查和至少一个真实任务验证记录。
- Demo 首次流程稳定通过，且失败能给出可执行原因。
- 结果缺失、格式变化和成本不可信都会明确降级，而不是静默进入排名。
- Windows、macOS、Linux 的关键路径都有维护者或自动验证来源。
- 新 Adapter 有明确用户需求和维护责任人，而不是只因为“能接入”。

## 近期优先级

1. 提高现有 Adapter 的可运行率和失败可解释性。
2. 提高结果、成本和推荐的可信度。
3. 完成 Workbench 主入口迁移。
4. 让任务包目录和双语内容自动保持一致。
5. 用自愿、本地统计和真实用户研究决定下一阶段，而不是继续堆入口或 Adapter。

## 发布与回滚

- 发布：默认入口切到 Workbench，旧版继续保留。
- 回滚：将根路径重新指向旧版，不需要改动运行结果或用户数据。
- Adapter 冻结是产品约束，不删除任何现有 Adapter。
- 本地统计仍默认关闭；关闭后不写文件、不发请求。
